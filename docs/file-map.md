# File Map

What each listed file does.

- `app/models/track_change.rb` — `TrackChange`: which per-kind targets a track change clears, the one statement of the rule; pure.
- `app/forms/profile_update.rb` — `ProfileUpdate`: `PATCH /profile`'s form. Checks the posted shape, runs the stale-page and track-choice checks under the user-row lock, saves through `LevelChange` in one transaction, and returns an `Outcome` the controller maps to JSON; which values a field allows stays with `User`'s validators.
- `app/models/level_change.rb` — `LevelChange`: one profile save's level bookkeeping, in the order `ProfileUpdate` calls it: clear the targets a track change covers, record cutoffs for kinds whose rung moved, then write the applied event rows.
- `app/models/level_suggestion.rb` — pure proposal rules: one-rung moves up and back along junior, mid-level and senior, each kind judged on its own results, and the evidence counts a card and an event row show.
- `app/models/level_suggestion/evidence.rb` — bounded, preloaded reviewed-response history projected into stamped, answered, rubric-graded results.
- `app/models/reviewed_section_results.rb` — `ReviewedSectionResults`: which sections of one submitted, reviewed response count as evidence of work at a rung, optionally only under the current rubric. Pure over the response it is given; shared by `LevelSuggestion::Evidence` and `CompetencyGate::Evidence`.
- `app/models/competency_gate.rb` — `CompetencyGate`: the pure fold that earns a day's size from reviewed days, with the brake. `DailyPlan.size_for` calls it once per plan.
- `app/models/day_size.rb` — `DaySize`: the day's planned count and its reason, from the Daily sections setting, the completion count and the gate's `Plan`. Pure; its `Decision` also answers whether the brake is on, for the coverage exception, and what the `[set_size]` line logs.
- `app/models/size_forecast.rb` — `SizeForecast`: whether tomorrow's Automatic set will be larger, or smaller because of the brake, than today's planned one, for the submitted dashboard's size lines.
- `app/models/competency_gate/evidence.rb` — the gate's only query: every rubric-stamped reviewed day, oldest first, in batches, as `CompetencyGate::Day` values, each carrying the pair its row was planned with.
- `app/controllers/welcome_controller.rb` — the first-run experience question; choices save through `ProfileUpdate`.
- `app/controllers/level_suggestion_dismissals_controller.rb` — records Not now and removed-kind cutoffs for the current user under the user-row lock, refusing a stale shown step with a 409, with a `dismissed` or `removed` event row for each kind whose cutoff moves forward.
- `app/models/level_suggestion_step.rb` — `LevelSuggestionStep`: one move a card or Setup showed, and the boundary check on the steps they post.
- `app/models/level_suggestion_event.rb` — `LevelSuggestionEvent`: one row per answer to a level suggestion (`applied`, `dismissed`, `removed`) with the evidence counts behind it; builds applied rows by rung, with `skill_level_edit` for a kind the skill level moved, from the state `LevelChange` passes in from before the save.
- `app/controllers/daily_kinds_controller.rb` — `PATCH /daily_kinds/:place`: maps a `DailyKindSwap` outcome to JSON, the reply, new pair and every daily card's re-rendered panel on a save, a 409 with the current pair and those panels for a stale page (panels only for the generation the page posts as `draft_scope`, else a `set_changed` sentence), and a 422 naming the reason for every other refusal
- `app/controllers/level_suggestion_answers_controller.rb` — counts an answered proposal, which decides whether the next one applies in place or links to Setup.
- `app/views/dashboard/_level_suggestion.html.erb` — submitted-day proposal with counts from the evidence, a removable list when several kinds share a destination, and in-place Apply/Not now saves.
- `app/views/api_keys/_level_suggestions_switch.html.erb` — the "Suggest level changes" switch at the top of Setup's Exercise mix, for every account; its `level-suggestions-switch` controller takes focus when the card's link asks.
- `script/prepare_junior_ladders.rb` (+ `script/junior_ladder_preparation.rb`) — operator coverage report; explicit `--run` queues shared-reference refreshes using the operator's key.
- `spec/requests/existing_account_pages_spec.rb` — exact pre-track Dashboard, Setup, Account and History snapshots. Propshaft digests in `/assets/` paths become `-DIGEST` before comparing, so editing a controller or an image does not move them; the layout's inline CSS and the `?v=` query on public icons still do. `UPDATE_PAGE_SNAPSHOTS=1` intentionally rewrites fixtures; never use it to conceal a learning-track regression.
- `spec/prompts/duck_prompt_characterization_spec.rb` — the duck's exact system, history, prompt and request settings for a first turn and a turn with history, and that string-keyed stored turns send the same bytes (`spec/fixtures/duck_prompt_snapshots/`), kept apart from the generation snapshots, whose spec fails on any file it did not write. `UPDATE_PROMPT_SNAPSHOTS=1` rewrites them; only a deliberate duck prompt change should.
- `app/models/duck_thread.rb` — `DuckThread`: each exercise's stored duck threads, keyed by section; the one authority for a section's turns, user-turn count and version, appending under the exercise lock and a version check, and counting clears. Read by nothing in generation, review, the judges, mastery or planning.
- `app/jobs/sweep_duck_threads_job.rb` — daily: deletes duck threads whose exercise is older than `DuckThread::KEPT_FOR` (365 days).
- `spec/services/duck_thread_isolation_spec.rb` — fails if generation, review, the judges, mastery or planning code reads `DuckThread`.
- `app/clients/ai_service.rb` — provider-agnostic base: provider orchestration through the `#call(request)` template, the `AiService::Request` value each call carries and `.request_for`, which builds it from the purpose's row in `CallProfiles::BY_PURPOSE`, JSON parsing, usage logging. The generation prompt is rendered by `GenerationPrompt`, which this class builds through its private `#generation_prompt` factory and hands to `ExerciseDraft` as a callable, with `#generate_problem_set` for the call and the parse; `#annotate_retention_concept` stays here as that prompt's retention callable because `RealSource` lists it as a curated excerpt. Owns `#assess_difficulty`'s deliberately narrow signature; `DailyResponse.usable_difficulty` owns what a storable/renderable assessment is, and is applied on write and again on read. Also owns the two-stage entry point: `#generate_judged_exercise` drafts through `ExerciseDraft`, then hands the draft to `JudgedGeneration`
- `app/prompts/generation_prompt.rb` — `GenerationPrompt`: `.system_prompt` renders the generation system prompt from the language's coach and focus; an instance renders the generation prompt and its JSON schema from the plan, history, difficulty and ladders as whole values, `only:` and `fixed_concept:` narrowing a retry to one kind; reads no database, clock or random state. Includes `GenerationPrompt::ConceptGuidance`
- `app/prompts/generation_prompt/concept_guidance.rb` — `GenerationPrompt::ConceptGuidance`: the one prompt line per concept group, each named from its `ConceptVocabulary` constant and stated once for every section
- `app/prompts/prompt_standards.rb` — `PromptStandards`: prompt text several families share, `PLAIN_LANGUAGE_STANDARD`, `.explain_differently_standard` and `.prior_framings`
- `app/prompts/section_context.rb` — `SectionContext.render`: one section described for a prompt (the duck and the difficulty assessment), field by field so no answer key reaches it
- `app/prompts/pseudocode_prompt.rb` — `PseudocodePrompt`: the pseudocode critique and translation prompts; `.critique` and `.translate` return the `system:` and `prompt:` for `AiService.request_for`, so the text has one home
- `app/prompts/concept_reference_prompt.rb` — `ConceptReferencePrompt`: the concept reference prompt and its reframe; `.generate` and `.reframe` return the `system:` and `prompt:` for `AiService.request_for`
- `app/prompts/recognition_guide_prompt.rb` — `RecognitionGuidePrompt`: the recognition guide prompt; `.generate` takes the group and its subject and returns the `system:` and `prompt:` for `AiService.request_for`
- `app/prompts/explain_differently_prompt.rb` — `ExplainDifferentlyPrompt`: the prompt that re-explains a reviewed section's missed points; `.generate` takes the question, answer, missed points and earlier framings as values and returns the `system:` and `prompt:` for `AiService.request_for`
- `app/prompts/follow_up_prompt.rb` — `FollowUpPrompt`: the prompt that answers a follow-up question about a reviewed section; `.generate` returns the `system:`, `history:` and `prompt:` for `AiService.request_for`
- `app/prompts/duck_prompt.rb` — `DuckPrompt`: the duck's system prompt and the canned explain request its button sends; `.generate` takes one section's data, the new message and the thread, and returns the `system:`, `history:` and `prompt:` for `AiService.request_for`
- `app/prompts/difficulty_prompt.rb` — `DifficultyPrompt`: the post-review difficulty assessment's prompt and its level guidance; `.generate` takes the coach and the sections and returns the `system:` and `prompt:` for `AiService.request_for`
- `app/prompts/section_judge_prompt.rb` — `SectionJudgePrompt`: the prompt for the judge that checks one generated section; `.generate` strips answer keys and server stamps and returns the `system:`, `prompt:` and `response_schema:` for `AiService.request_for`
- `app/prompts/review_prose_judge_prompt.rb` — `ReviewProseJudgePrompt`: the prompt for the pass that rewords a graded review's prose; `.generate` takes the kind, the coach and the review's prose and returns the `system:`, `prompt:` and `response_schema:` for `AiService.request_for`
- `app/prompts/review_prompt.rb` — `ReviewPrompt`: the two-stage review's text and `RATING_RUBRIC`; `.day_system` renders the day-level system prompt from each section's values, and `.section_prompt` the per-section grading prompt at the rung it is handed
- `app/services/generation_diagnostics.rb` — `GenerationDiagnostics`: the log lines a generation writes (`[set_size]`, `[unusable_section]`, `[retention]`, `[shared_concept]`, `[coverage]`, `[difficulty_diagnostics]`), with answer-key fields stripped from the delivered set through `ExerciseSection.without_answer_keys`; writes nothing but logs
- `app/prompts/generation_prompt/difficulty_guidance.rb` — `GenerationPrompt::DifficultyGuidance.render`: the difficulty block, every planned kind at its rung with ladder rungs and lock lines; the prompt and `GenerationDiagnostics#kind_difficulty` both call it, so the logged character count is the text sent
- `spec/support/generation_prompt_helpers.rb` — `render_generation_prompt`, `generation_schema` and `plan_for`: render a prompt or schema from a `DailyPlan::Result` built on legacy test defaults (`PLAN_DEFAULTS`), with the real `AiService#annotate_retention_concept` bound from a service that can never open a connection
- `app/services/judged_generation.rb` — `JudgedGeneration`: the two-stage path after the draft. Fans the judge out a section at a time, retries a rejection, or a planned section ingest refused, up to the plan's `judge_retries` for that kind (twice for a daily kind, once otherwise) with its concept fixed, drops a rejected last retry, re-judges a design comparison's edits, and hands the final set to its `finish` callable (`ExerciseDraft.finish`, from `AiService`). It reaches the provider only through `JudgedGeneration::Provider` (`judge_section`, and `retry_section` taking the draft, kind and concept, as callables built fresh per call), so its specs need no provider subclass. `JudgedGeneration::UnhostedConcepts` names the planned concepts a drop left without a host. Every judge pass on a kind the judge solves blind becomes a `JudgedGeneration::Solve`, kept per kind by `JudgedGeneration::SolveChain`, which decides `shipped` and `never_shown_reason` from what the run kept; the solves come back on `AiService::JudgedSet#solves`, never inside `outcomes`
- `app/models/generation_ladders.rb` — `GenerationLadders.for`: loads each requested kind's difficulty-ladder rungs from `ConceptReference`, at that kind's rung, for the vocabulary the day's `code_review` mode allows, merged by level and each truncated to `ConceptReference::MAX_LADDER_RUNG_LENGTH`. `ExerciseDraft` reads it for the draft and the single-section retry, and `GenerationPrompt` renders the result
- `app/services/exercise_draft.rb` — `ExerciseDraft`: drafts the day's set (plan, history, difficulty, ladders, prompt, one provider call, ingest) into an `ExerciseDraft::Draft` that carries its user and language, retries one section from that draft with its concept fixed, and finishes a set by recording suggested concepts and the generation diagnostics. It reaches the provider only through `ExerciseDraft::Provider` (`prompt`, `generate` and `record_suggestion`, built by `AiService#exercise_draft_provider`), so its specs need no provider subclass
- `app/models/generation_deadline.rb` — `GenerationDeadline`: refuses a provider call whose worst case (`AiService::Request#worst_case_seconds`) would end after the deadline, raising `ProviderError::DeadlineError`. `AiService#call_and_log` checks it first, after the request is built; `#leaving` keeps time back so a retry reserves its re-judge. `NONE` is the no-deadline default
- `app/models/problem_set_ingest.rb` — the generation boundary: holds concepts to their closed vocabulary, bounds scaffolds and diagrams, runs each resolved section's own `.reject_unusable!` check, leaving a refused section out and reporting it on `Result#unusable_sections`, calls each resolved section's `.arrange!` (the Parsons scramble, the design comparison's A/B order), and logs a section the day never asked for. Writes nothing to the database — off-vocabulary concepts come back on the `Result` for `ExerciseDraft.finish` to record, so a rejected set structurally cannot leave a `SuggestedConcept` row behind, and its specs need no database. Not side-effect free, though: `warn_unrequested_sections!` logs.
- `app/models/daily_plan.rb` — the day's plan (third section, reinforcement, the shared concept, retention checks and the ones left waiting, the coverage addition, `code_review` mode and the real-source excerpt grounding it, if any), decided before any provider is contacted; pure decision, no prompt or HTTP
- `app/models/coverage_exception.rb` (+ `coverage_exception/history.rb`) — `CoverageException`: whether a two-section Automatic day gains one optional section, and which; pure. `.expected_gap_weekdays` states how often one candidate kind recurs, for the swap sheet. `History.for` is its one-query loader
- `app/models/shared_concept.rb` — `SharedConcept`: which reduced-tier concept both daily sections take, from a host the day left free; pure
- `app/models/day_hosts.rb` — `DayHosts`: which kinds can tag a concept today, bucket and strict no-rung vocabulary; pure
- `app/models/real_source.rb` — `RealSource`: the curated registry of Code Gym's own methods and migrations a `code_review` may be grounded in, the per-user least-recently-seen pick over it, and the trace it reads back from `problem_set`. Closed lists, one class per excerpt kind — adding an entry is a line, adding a kind is a class
- `app/models/invite_code.rb` — `InviteCode`: a code's digest, seats, deadline and trial terms; `.mint` prints the code once, `#redeem!` takes a seat atomically
- `app/models/pending_trial.rb` — `PendingTrial`: a trial asked for on the public trial page, kept in the session until the emailed code is entered
- `app/controllers/concerns/login_code_requests.rb` — `LoginCodeRequests`: mailing a login code and the limits on asking, shared by the login form and the trial form
- `app/models/provider_credential.rb` — `ProviderCredential.for(user)`: own key, no key, or the house key for an active trial; raises for an ended one
- `app/models/trial_allowance.rb` — `TrialAllowance.check!`: the per-account cap and the house-key guard, run ahead of every house-key call
- `app/models/house_keys.rb` / `trial_mode.rb` — the house keys and guards from ENV, and the kill switch
- `app/controllers/trials_controller.rb` — `/trial/start` for someone signed out and `/trial` for a keyless account: the code, the provider, the data notice and consent, and a trial's standing once it has begun
- `app/models/trial_status.rb` — `TrialStatus`: a trial's standing for its pages: days left, today's calls against the cap, the day it ended
- `script/mint_invite_code.rb` — mints one invite code and prints it once
- `script/record_competency_gate_fixture.rb` — rebuilds `spec/fixtures/competency_gate/default_pair_histories.json` from the gate as it stands; run only for a deliberate gate change
- `app/models/provider_failure.rb` — `ProviderFailure`: the kind of failure a page can explain, from the error the boundary rescued; pure
- `app/models/provider_error.rb` — `ProviderError` and its subclasses: the failures a provider call raises, carrying the HTTP status, quota id, retry wait and provider. Each class states its own codes (`.error_code`, `.failure_code`, `.judge_fallback_reason`, `.failure_kind`), inherited by its subclasses, and `AiService.error_code_for`, `.failure_code_for`, `.judge_fallback_reason` and `ProviderFailure.classify` read them
- `app/models/setup_error.rb` — `SetupError`: a problem with an account's setup or the app's own data (no usable provider, the fake provider outside a local environment, an unsupported language); not a `ProviderError`, but rescued and recorded beside one and classified by `ProviderFailure` as `setup`
- `app/models/reset_clock.rb` — `ResetClock`: when a failed call's limit lifts, for the sentence's reset time; pure
- `app/models/provider_failure_text.rb` — `ProviderFailureText`: one failure as a sentence for a person, from the `provider_failures` locale table, in the reader's zone and against the clock; `#full` for a page, `#brief` for a status line
- `app/models/concept_reference_failures.rb` — `ConceptReferenceFailures`: the per-user, cache-held note of why a write-up stopped, read by Learn's status endpoint
- `app/controllers/concerns/provider_failure_rendering.rb` — `ProviderFailureRendering`: the one way a controller turns a provider error into a sentence or a JSON error
- `app/models/judge_verdict.rb` — `JudgeVerdict`: the judge's reply held to its closed vocabulary, the way `ProblemSetIngest` holds a problem set. A status outside three, an issue type or principle outside the lists, a rewrite of a field that is not prose, or blank evidence or reason is invalid output rather than a judgment. Pure; its specs need no database
- `app/models/concerns/claimable.rb` — `Claimable`: a timestamp column held as a claim on a paid provider call. A model states the column and the stale window once (`claim :reviewing, column:, stale_after:`) and gets `#claim_<name>!`, an owner-only `#release_<name>!(token)` and `#<name>?`, so the predicate and the claim query share one staleness rule. Used by `DailyResponse` (review) and `DailyExercise` (regeneration)
- `app/models/concept_vocabulary.rb` — `ConceptVocabulary`: the closed concept lists, each language's lists (`LANGUAGES`), and the two questions asked of them, which concepts are valid when a provider returns them (`.for_section`) and which a kind may be asked for (`.selectable_for_section`). Domain data, so it never reads `AiService`; its specs need no provider or database
- `app/models/language_prompts.rb` — `LanguagePrompts`: each concept bucket's prompt wording (label, coach, focus, test framework, schema artifact); `.for` raises `SetupError` on an unsupported language
- `app/models/scenario_pools.rb` — `ScenarioPools`: the scenario settings each flavor `DailyPlan` rolls offers the generation prompt
- `app/models/concept_bucket.rb` — which vocabulary bucket a concept's history records under (architecture/plan_review/ambiguity_hunt are each language-independent; everything else buckets by the day's language)
- `app/models/kind_preferences.rb` — `KindPreferences`: a user's stated weight and exclusion bias over rotating kinds, as plain values `SectionRotation` takes instead of a `User`, so its specs need no database. `.none` is the untouched default; a stored value outside `MULTIPLIERS` reads back as that default rather than reaching `WeightedRoll`. `#offered` is the kinds a pair and its exclusions leave pickable
- `app/models/kind_difficulty.rb` — `KindDifficulty`: a user's stated difficulty target and lock per section kind, as plain values the same way `KindPreferences` is. A level outside `LEVELS` reads as unset and a lock on an untargeted kind reads as unlocked, so an orphaned lock can never suppress easing the user did not validly choose. `#rung_for` is the rung a kind is pitched at today, target or skill level, the one place a skill level is read as a rung
- `app/models/concept_hosts.rb` — `ConceptHosts`: which section kinds can host each (concept, bucket), derived from `ConceptVocabulary.selectable_for_section` across every `code_review` mode and the user's languages; read by `LadderCoverage` and the Progress page
- `app/models/ladder_coverage.rb` — `LadderCoverage`: which of the pairs `ConceptHosts` offers each kind already carry a ladder rung, for every kind whether or not it is targeted — callers filter for targets themselves; gaps cover only the kinds `KindPreferences#offered` returns
- `app/models/rung_ledger.rb` — `RungLedger`: the rung a user holds per concept, from stored responses and the `pitched_at` stamps; pure over the rows it is given
- `app/controllers/progress_controller.rb` — the `/progress` page: Learn's grouping, `RungLedger`'s standings, `ConceptHosts` and `KindPreferences#offered` for what is offered
- `app/models/daily_kinds.rb` — `DailyKinds`: which kinds every set holds. Reads the user's sparse `daily_section_kinds` (empty means `DEFAULT`) and normalizes it on read, reads a stored day's pair from `plan_notes["daily_kinds"]` (no key means `DEFAULT`), states the write-time rules `User` validates, and answers which places exist (`.place?`) and a pair's stored form (`.stored`). `ExerciseSection.layout(daily:)` turns a pair into the day's slots
- `app/models/daily_kind_swap.rb` — `DailyKindSwap`: one swap of one daily place. Refuses an unknown place or kind, a stale preferences version, the current or other daily kind, a second fourth kind, or a pair that empties an optional slot; otherwise saves the pair under the user-row lock and writes one `DailyKindSwapEvent`. Returns an `Outcome` with the server's reply sentence and the want-it-today line; `.refusal` answers the pair rules for the picker
- `app/models/daily_kind_swap/picker.rb` — `DailyKindSwap::Picker`: what one daily card's swap control shows. `.for_day` keys a picker by each delivered daily card's kind; each option's state and note come from `DailyKindSwap#refusal`, and a refusal of the place's own kind (an ended trial) closes the picker
- `app/models/daily_kind_swap/consequences.rb` — `DailyKindSwap::Consequences`: pure; the sentences about the incoming kind and the warning about the outgoing kind that the swap sheet's footer shows for one option before it is swapped in
- `app/models/daily_kind_swap_event.rb` — `DailyKindSwapEvent`: one row per saved swap in `daily_kind_swaps` (place, both kinds, the outgoing section's state in today's set, today's planned size, the size setting)
- `app/models/exercise_section.rb` (+ `app/models/exercise_section/`) — the registry of section kinds (code_review, design_comparison, pattern, challenge, architecture, security_review, parsons_problem, plan_review, ambiguity_hunt, pseudocode_to_code); one class per kind answers which are in the default daily pair (`.default_daily?`, which `DailyKinds::DEFAULT` reads), which slots a daily pair gives a day (`.layout(daily:)`, `.optional_slots(daily:)`), which are thirds, which are fourths, which vocabulary they draw from and how it narrows that list for generation (`.narrow_vocabulary`, given an optional rung), which fields are answer key (`.answer_key_fields`), what the provider boundary refuses (`.reject_unusable!`), any extra judge instructions (`.judge_guidance`), how a resolved section is arranged after it is accepted (`.arrange!`), whether the judge solves it blind (`.judge_solve_options`, `.keyed_solve`, `.solve_matches_key?`), which show improved code, which scaffold their answer, and — via `.schema_fragment` / `.generation_guidance` — what the generation prompt says about them. `AiService` assembles those fragments, and each language's prompt wording is `LanguagePrompts`; it no longer branches on section keys — or on kind identity — to build them. `.generation_guidance` takes a uniform context (`vocabulary:, label:, mode:, artifact:, test_framework:, source:, rung:, alongside:`, the last being the other kinds requested with it, not the day's kinds) that every kind receives and each reads only its own part of; kinds that read none of the optional values absorb them with `**`. Adding a kind means adding a class here, not editing `AiService`.
- `app/models/code_format.rb` (+ `app/models/code_format/ruby.rb`, `app/clients/code_format/javascript.rb`) — `CodeFormat`: re-indents a batch of exercise code in the day's language, RuboCop's Layout cops for Ruby and Prettier (through Node, so an adapter in `app/clients`) for JavaScript, handing back what it cannot format unchanged
- `vendor/prettier/` — the Prettier package and `format.mjs`, the Node script `CodeFormat::Javascript` runs
- `app/models/worked_example.rb` — `WorkedExample.parts`: a stored `guide_worked_example` split into code and prose runs for the Learn page; pure
- `app/models/code_highlight.rb` — `CodeHighlight`: Rouge highlighting for a code block, its line formatter, the lexer map and the cache key; `SyntaxHighlightingHelper#highlighted_code` is the one call site views use
- `app/helpers/answer_scaffolds_helper.rb` — the textarea pre-fill value, so the scaffold rule is stated once rather than per textarea
- `app/models/exercise_section/design_comparison.rb` — the second default daily kind: two working pieces, a server-rolled A/B order, the `pick:` answer encoding, its rung-aware vocabulary allowlist, and the judge's blind-solve facets
- `app/views/responses/bodies/_design_comparison.html.erb` / `answers/_design_comparison.html.erb` — the two pieces in their own disclosures; the pick fieldset and reason textarea, which the `comparison-answer` controller writes into the hidden answer, plus "What decides it" once reviewed
- `script/report_answer_positions.rb` (+ `script/answer_position_balance.rb`) — read-only count of where the better design-comparison piece was shown, totals only
- `script/solve_agreement.rb` — `SolveAgreement`: prints blind-solve agreement per model, rung and concept for `script/compare_models.rb`'s judge modes, never a solve or a key
- `app/clients/claude_service.rb` / `gemini_service.rb` / `openai_service.rb` — each implements `request_body`, `read_result`, `raise_for_status`, `provider_name` and `build_connection` behind `AiService#call`, defines the `API_URL` it posts to, and owns its model-per-purpose table and private `route_for`; `OpenaiService` also overrides `long_running?`
- `Archspec.rb` — the layer rules `archspec check` enforces in CI's lint job: models and prompt classes reference no service and no client, except `AiProvider` (`docs/decisions/folders-by-layer.md`)
- `spec/support/isolation_scope.rb` — `IsolationScope`: the files the isolation specs scan, every file under `app/models`, `app/services`, `app/jobs`, `app/prompts` and `app/clients`; each spec subtracts the owners it names
- `app/models/section_kind_settings.rb` — `SectionKindSettings`: the rules for a user's section-kind preference columns (weights, exclusions, levels, locks, daily kinds), built from their values and stored values: `#problems` for `User`'s one validation, `#changed?` for the version bump, `#emptied_slots` for `DailyKindSwap`, and `#keep_unrendered` for an Exercise mix save. Pure; its specs need no database
- `app/models/call_profiles.rb` — `CallProfiles`: each purpose's call settings (`BY_PURPOSE`: token cap, read timeout, caching, single attempt, allowed truncation), the shared timeouts and retry counts, and the worst-case call times built from them (`.worst_case_seconds_for`, `.call_budget_seconds`, `JUDGED_GENERATION_BUDGET`). Names no provider, so models, views and jobs read call timing here
- `app/models/ai_provider.rb` — closed provider registry for dispatch, key detection and user validation; provider classes own the key patterns and environment restrictions. Also the one model that reaches the provider classes, for `.daily_quota_reset_at` (the provider's own quota day), so other models ask it instead
