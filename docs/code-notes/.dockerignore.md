# .dockerignore

`.dockerignore` keeps files out of the build context, so `COPY . .` in the `Dockerfile` never sends them. Rails generated most of it; see https://docs.docker.com/engine/reference/builder/#dockerignore-file.

- Git data (`/.git/`, `/.gitignore`), bundler config and environment files.
- The key files (`/config/master.key`, `/config/credentials/*.key`), logs, temporary files, pidfiles and development storage.
- Built assets (`/node_modules/`, `/app/assets/builds/*`, `/public/assets`).
- CI service files (`/.github`), the dev container (`/.devcontainer`) and the Docker files themselves (`/.dockerignore`, `/Dockerfile*`).
- `/vendor/prettier/node_modules`, because the image installs it with `npm ci`.

`bin/comment-check` reads a `.dockerignore` comment only when the line starts with `#` in the first column, the stricter reading. A `#` anywhere else is part of a pattern.
