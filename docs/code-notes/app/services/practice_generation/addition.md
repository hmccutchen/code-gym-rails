# PracticeGeneration::Addition

Reuses the parent's capture validation and judge-solve persistence. Capture
and commit use the addition service's owner-first lock wrapper. A requested
kind travels in the immutable context, so the ordinary provider pipeline asks
for exactly that kind without a separate generation API.

Append merges one key rather than calling replacement. It does not destroy
response data or alter generated_at. Additional assignment notes live outside
the strict initial schedule envelope. Only the touched kind's continuation
service merges on a format-3 predecessor; a changed predecessor rejects the
candidate. Legacy notes use the current translation rules.

See docs/decisions/on-demand-exercise-additions.md for lifecycle and deployment.
