# One finish action

the Submit button is always clickable. The server decides whether the day can be submitted (`DailyResponse#submit_blocker`): at least one section answered and every answered section rated. A nudge under the button shows the blocker from the latest autosave reply, and a click the server refuses shows the same sentence and moves focus to it. Typing saves 800 ms after the last keystroke; a rating click, leaving an answer and a design comparison pick or Parsons move save at once, so the nudge follows within one round trip. The browser holds no copy of the rule, so the two cannot disagree; the cost is that the nudge, progress and hint lock update after a save rather than on each keystroke. Answers and rating land in one `ResponsesController#create` call, and a successful submit fires the review from that same click — still a separate request, still exactly one review per day, just no second click to reach it. Draft ratings are set-only: `#create` accepts only valid enum values and preserves ratings while answers are edited or cleared. At submission it slices ratings to `answered_sections`, so a cleared, too-short, or scaffold-only answer leaves no self-assessment behind. Partial answer payloads merge into the draft before this slice; omitted answers remain unchanged, and explicit empty strings clear them. The form stays inert during submission and the review handoff, keeping its visible answers and ratings at the submitted snapshot; a failed submission restores editing. The progress label reports answers only; the nudge reports readiness. The dashboard requires JavaScript; rating, autosave, progress, and submit are all driven by `answer_form_controller.js`, a Stimulus controller. `#create` refuses a submit that `submit_blocker` would block, with a 422 carrying the nudge's sentence, the answered sections and the blocker, and nothing saved, not even the draft the request carried. Accepting one would bill a review of every section, freeze the day and count it toward the streak.
A refused or dropped submission restarts the draft autosave it canceled, so
the last edit survives without another keystroke. A submission that got no
reply restarts it too, since the server may have committed the submit and
lost only the reply; that autosave then reloads into the submitted page. If submission succeeds but
the browser cannot start the review POST, the page explains that the answers
were saved and reloads the submitted state with its manual review button.
It never restores an editable draft after an acknowledged submission.
