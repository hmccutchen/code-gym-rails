# Difficulty targets and locks

a user may set any section kind — code_review and pattern included, since a level needs no alternative candidate — to `junior` / `mid_level` / `senior` / `principal_engineer` (`KindDifficulty::LEVELS`, which `User::SKILL_LEVELS` reuses, and deliberately disjoint from the review grades). Unset follows `skill_level`; a target replaces it as that section's baseline, with tier annotations and rating adjustments still applying on top; a lock suppresses the `(reduced)` easing rule and both rating adjustments for that section, with no exceptions, including a concept's first exposure. That last part is a deliberate tradeoff: a kind locked at `principal_engineer` can present an unfamiliar concept at full difficulty on day one. Lock changes prompt text only — `DailyPlan`, `ConceptMastery` and `User#concepts_*` never read `KindDifficulty`, and specs pin it — so unlocking reads current evidence. The block is appended by `GenerationPrompt::DifficultyGuidance.render`, grouped by level, and grounded by per-concept ladder rungs written in the same `#generate_concept_reference` call as the reference and guide. It lists every kind on the plan at its rung, the target or else the skill level, and a kind renders the same either way, so a target equal to the skill level changes nothing in the prompt (`level_suggestion_isolation_spec` pins it). Until 2026-10-15 it listed targeted kinds only, and an untargeted kind's level reached the model as the profile's "Skill level" line alone; every account's generation prompt changed when that ended. A retention check in any section is pitched at that section's level; raising a target after mastery makes the next check harder than the evidence behind it, an accepted consequence. `LadderCoverage` answers how grounded each kind is at its rung; `POST /learn/prepare_ladders` rewrites the ungrounded concepts behind every section's level, targeted or not, skipping kinds the user excluded, the one scoped exception to the Learn tab's no-bulk-rewrite rule, and since `ConceptReference` is shared, that rewrite reaches every teammate. One press queues one billed job per gap, which can be a hundred or so on an account that never prepared any; `PREPARE_PER_HOUR` counts presses, not jobs. A trial account is never offered it (`User#prepares_ladders?`), so a house key never funds a shared rewrite. The ladder text now reaches every account's generation prompt, and a retry carries only its own kind's rungs; the added input tokens are unmeasured, and `ApiUsage` rows under `purpose: "generate_exercise"` before and after 2026-10-15 are the way to measure them. Weights and difficulty share `section_kind_preferences_version`, so a stale tab is refused whichever half it touched. `AiService::MAX_LADDER_GUIDANCE_CHARS` bounds the block's worst case, every rung at its full length: it went from 48,000 to 54,000 on 2026-10-11, because the `mid_level` rung lets a day hold four kinds at four levels, and its spec measured 53,632; the block's reworded opening line brought that to 53,668 on 2026-10-15.
